# 面向现场复盘的 BEV 项目审阅

审阅日期：2026-10-02。目标：在录像时间范围内自由旋转、俯视、缩放，判断本车、附近车辆与车道的相对位置，并能回到原视频核对事件。

## 结论

建议保留现有 React / Three.js 播放器和六路视频组织能力，把主要投入放在“时空一致的语义场景重建”。当前已经有旋转视角、目标选择、时间轴和车辆模型；不足主要来自几何观测、坐标变换、车道建模和验证，而不是模型外观。

推荐交付形态是可自由观察的 2.5D 语义场景：道路曲线、车辆有向包围盒、稳定 ID、轨迹、原视频证据。此形态足以承载用户描述的复盘需求。写实纹理或新视角视频可以以后添加，但不能替代位置验证。

目前不能承诺车机级精度。仓库没有独立距离真值或完整相机标定验收；用同一深度模型估计焦距、尺度再验证自身结果，不构成独立精度证明。

- `npm run build`：通过，有前端包体积警告。
- `npm run lint`：通过。
- 对 `public/reconstruction/*-bev-timeline.json` 运行现有验证器：17/17 通过。
- 统计现有缓存：966 个场景帧、7,172 条目标记录、39 帧没有车道；按片段和 ID 分组共 1,083 条轨迹，中位数为 3 次输出观测。短轨迹可能包含目标正常进出视野，不能直接当作 ID 切换真值。

本次为代码、缓存与最小复现实验审阅，没有重跑完整模型推理、逐帧人工标注原视频，也没有进行浏览器视觉验收。下述厘米/米级精度指标均是待验证的工程目标，不是已达到的结果。

## 优先问题

### 1. P1：消失目标的外推混用了速度坐标语义

位置：`src/utils/bevScene.ts:27–36`；`tools/bev_tracker.py:_Track.predict/to_object`。

跟踪器先使用目标速度预测，再减去本车位移并旋转到新的自车坐标系。因此，有正常遥测时，输出的 `vx/vz` 是用当前车身坐标轴表达的世界运动速度，并不是自车相对坐标的时间导数。前端在下一帧找不到相同 ID 时，直接执行 `z += vz * dt`，没有扣除自车运动。

实测缓存 `2026-07-23_07-54-38` 的 `track-0094`：54 秒时 `(x,z)=(-4.214,2.734)`、`vz=25.553 m/s`；调用 `nearestFrame` 到 54.49 秒后得到 `(-4.482,15.255)`，不到半秒向前移动约 12.52 米，且仍通过前端显示过滤。该数值是插值目标位置，屏幕上还会叠加阻尼动画；它不是对真实车辆运动的测量。

修复：明确世界速度与相对速度字段；有位姿时先在统一世界坐标插值再变换回当前自车坐标。暂缺位姿时，失配目标应保守保持最后位置并淡出，不能直接用世界速度做相对位置外推。覆盖同速跟车、静止障碍物和本车转弯的回归场景。

### 2. P1：车道没有补偿自车运动，曲线又被压成直线

位置：`tools/bev_tracker.py:391–414, 479–511`。

自车位移与航向变化仅传给车辆轨迹，车道轨迹没有相同变换。最小复现：先确认一条 `x=1.85m` 的车道，下一秒本车转向 5°、车道暂时漏检，输出仍是完全相同的 `x=1.85m` 直线。静态道路在旋转后的自车坐标中不应保持不变。

此外，检测器生成的二次曲线被 `_lane_parameters` 重新拟合成直线，`_LaneTrack.polyline` 只输出直线。对转弯、变道、匝道和分合流的复盘都不够。

修复：车道保存为事件世界坐标中的带 ID 曲线/折线，保留曲率；只在渲染时转到自车坐标。持续跟踪、漏检保持和跨相机关联都用同一套位姿。

### 3. P1：车旁、车后的车道包含未明确区分的外推

位置：`tools/reconstruct_bev_timeline.py:82`；`src/components/BevView.tsx:234–299, 566`。

场景轨只检测前视车道。前端把它延长到车后 10 米，道路面延长到车后 12 米；没有车道时还会根据方向盘角度画两条相距 3.7 米的参考线。渲染没有逐段明确标注哪些来自观测、哪些属于外推。

这会影响用户对车子是否压线、正在进入哪条车道的判断。转动视角看到道路，不代表这些道路位置已经被视频重建。

修复：实测、历史观测变换、短时预测和未知区域分别显示。接入侧/后视车道与路沿观测；不能由前视延长线充当周围真实道路。没有观测时保留未知区域，参考线默认关闭或明确命名。

### 4. P1：车辆表面观测点被当作整车中心

位置：`tools/moge_depth.py:box_ground_position`；`tools/reconstruct_bev.py:280–317`。

深度从检测框下部约 30% 区域取中位数，没有实例分割。观测可能落在车尾、侧面、轮胎、背景或遮挡物上。该点直接成为车辆模型的中心，长宽则来自固定类别尺寸，小汽车统一使用 1.9 × 4.5 米。

即使深度对可见车尾表面完全正确，整车中心也不在同一点。正对车尾且车长 4.5 米时，中心沿车长方向应相差约 2.25 米；这是几何示例，不是对现有缓存的真值误差统计。跨相机看见不同车身面时，中心定义不一致也会影响融合和 ID 接力。

修复：保存观测点及其语义，用实例掩码、可见面、朝向和尺寸先验联合拟合有向 3D 框；尺寸先验应是约束，不应当作实测尺寸。验证须回投到原视频，并分清车身中心距离和车身间净距。

### 5. P1：质量门主要验证“没有明显冲突”，不能验证“还原了现场”

位置：`tools/validate_bev_timeline.py:142–182`；`vite-bev-plugin.ts:validateTimelinePayload`。

最小复现：构造两帧空目标、空车道数据，标记 `rangeBackend=moge2, calibrated=true`，Python 质量门返回 `passed=true` 且没有警告。当前门限也不验证真实漏检率、目标 ID 正确性、相机回投误差和米制误差。

注意，真实空路段可以没有目标，不能简单用“目标数大于零”替代正确验收。应返回结构合法性、观测覆盖和几何验证三个独立状态；只有与原始证据比较后，才能说明重建质量。

前端“误差 ±x m”来自手设测量噪声下的滤波协方差，未包含完整标定和系统偏差，不能视为真实误差上限；YOLO 分数也不是位置准确率。

修复：建立人工核对集，补充漏检、ID 切换、回投、跨相机一致性、车道连续性与时间同步指标。缓存记录源视频、标定、模型和算法版本的指纹，避免修改算法后仍展示旧缓存。

### 6. P2：1 Hz 和逐文件独立跟踪限制事件复盘

位置：`vite-bev-plugin.ts:276`；`tools/reconstruct_bev_timeline.py:72–91`；`tools/bev_tracker.py:467–474`。

服务每秒只生成一个观测时刻，其间主要靠插值和动画。快速切入、急刹或短暂出现的目标可能发生在两个观测之间。跟踪状态每次生成单个片段时重新初始化，视频连续播放不代表跨分钟文件的目标 ID、车道和位姿连续。

六路抽帧使用相同的请求秒数，但产物没有保存实际帧 PTS 或同步残差，不能据此证明六路实现了逐帧同步。

修复：建立事件级时间轴和跨文件状态。先试验 5–10 Hz 检测/二维跟踪、较低频率深度关键帧与自适应补帧，在关键事件窗口提高密度；此频率是待性能测试的设计目标，不是当前机器的已测吞吐量。离线复盘可以使用前后帧联合优化，提高遮挡前后身份和轨迹的一致性。

### 7. P2：证据和轨迹显示缺少完整时空关联

位置：`tools/bev_tracker.py:281–300`；`src/components/BevView.tsx:613–623`。

跟踪器输出丢弃了检测框，跨相机融合也没有输出每个来源独立的观测明细，限制“点击某辆车，立即高亮对应录像证据”的实现。现有尾迹直接连接各时刻自车坐标点；可以解释为相对位置历史，但不能作为当前道路上的世界运动轨迹。

修复：保留来源文件、摄像头、实际帧时间、二维框/掩码、原始深度、观测/预测状态及关联置信度。增加事件世界坐标与每帧自车位姿，清楚区分世界路径和相对位置历史。

## 建议的实施顺序

### 第一阶段：消除可以确定的错误

1. 修复外推速度语义，并处理暂停、倒放与拖动时间轴时的确定性显示。
2. 给车道增加自车运动补偿，保留曲线与稳定 ID。
3. 明确标注外推车道、参考道路及短时预测目标。
4. 保存原始观测证据，修改质量状态和不确定度文案。
5. 为算法/标定变更建立缓存指纹和版本迁移。

此阶段改善可信度，但不应被宣称为完成米制重建。

### 第二阶段：用一段短事件证明位置可信

选择 20–30 秒、包含相邻车道车辆或切入行为的六路录像。人工标出关键目标 ID、二维框、车道和行为时刻。优先通过多视角重投影验证几何；如要量化米制误差，必须另有独立的尺度/距离参考。

建立完整相机模型：分辨率/裁剪对应的内参、畸变或已去畸变状态、六路外参、来源和残差报告。现有 MoGe 估计可作初值；安装高度和偏航仍是种子值，不能把 `calibrated=true` 当作验收。路面起伏与车身姿态也需区分。

在此基准上实现稳定自车位姿、实例观测到 3D 框的几何拟合、多摄像头关联及静态道路累积。用独立片段验证，避免只把当前片段调得好看。

### 第三阶段：完成复盘产品体验

- 俯视、斜视、跟随本车、固定世界视角，以及随时暂停旋转观察。
- 选中目标后显示过去/未来轨迹、所属车道、相对距离变化，并同步高亮来源画面。
- 连续事件时间轴跨越录像文件；关键时刻可跳转，支持慢放和逐帧核对。
- 变道、近距离交汇、制动等事件标记先作为候选提示，保留原视频核对入口。
- 距离超出可靠范围或发生遮挡时显示不确定性与未知区域。

## 候选验收目标

以下先在人工核对的短事件上评估，再决定是否扩大范围。

| 项目 | 候选目标 / 验证方式 |
| --- | --- |
| 坐标正确性 | 同速跟车不因自车速度产生虚假前冲；静止目标随本车运动正确变化 |
| 道路一致性 | 转弯与短时漏检后，历史道路经位姿变换与新的观测吻合 |
| 目标连续性 | 明确标注的关键车辆在无遮挡窗口内不换 ID，遮挡接力单独计分 |
| 近场位置 | 对可观测、已独立标定的 0–20 米目标，试验横向 P95 ≤0.5 米、纵向 P95 ≤1 米；需要独立距离参考 |
| 中远场位置 | 单列 20–40 米及更远距离的误差、漏检率，不混在总体平均值里 |
| 事件时刻 | 对人工标注的切入/交汇窗口，试验时间偏差 ≤0.2 秒 |
| 可追溯性 | 每个关键目标、关键时刻均能回到来源视频帧核对 |
| 播放一致性 | 同一时间点暂停、拖动到达、顺播到达的场景坐标一致 |

先完成短事件的证据闭环，再批量重建全部录像，是目前最能降低返工的路线。
